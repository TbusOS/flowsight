| 角色 | Agent | 职责 | 触发条件 |

## 触发方式

### 1. 手动触发完整审计

```
用户: 审计知识库覆盖率
系统: 启动 KB-Auditor → 生成报告 → 派发任务 → KB-* 并行开发 → KB-Reviewer 审核
```

### 2. 手动触发特定子系统审计

```
用户: 审计内存管理知识库
系统: KB-Auditor 针对 mm/ 审计 → KB-Memory 改进 → KB-Reviewer 审核
```

### 3. 开发后自动审核

```
用户: 完善 workqueue 知识库
系统: KB-IRQ 开发 → 自动触发 KB-Reviewer → 通过后提交
```

## 质量标准

### Pattern 要求
- 覆盖内核使用 > 100 次的 API
- 准确率 > 95% (误报 < 5%)
- 包含常见变体 (如 kmalloc, kmalloc_array, kmalloc_node)

### 调用链要求
- 从入口到用户代码完整
- 标注执行上下文变化
- 标注源文件位置

### 文档要求
- 中文描述
- context (type, can_sleep) 准确
- 至少 1 个代码示例

## 使用示例

### 完整审计

```
用户: 对知识库进行完整审计，找出不足并改进

系统:
1. KB-Auditor: 运行审计脚本，生成报告
   - 覆盖率: 78%
   - 发现缺失: regmap, clk, pm_runtime 等
   
2. 派发任务:
   - KB-Drivers: 补充 regmap/clk 支持
   - KB-Memory: 补充 pm_runtime 支持
   
3. KB-Drivers/KB-Memory: 并行开发

4. KB-Reviewer: 审核完成的修改

5. 通过后: Git commit & push

6. KB-Auditor: 验证改进
   - 新覆盖率: 85%
```

### 针对性改进

```
用户: 文件系统知识库覆盖率太低，重点改进

系统:
1. KB-Auditor: 审计 fs/ 和 core/vfs.yaml
   - 发现缺失: xattr, acl, quota, splice 等

2. KB-FS: 按优先级补充
   - P0: xattr 操作
   - P1: acl 支持
   - P2: quota 接口

3. KB-Reviewer: 逐个审核

4. 完成后提交
```
