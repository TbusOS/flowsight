# SuperClaude Framework - FlowSight 交互设计技能

## 技能概述

| 属性 | 值 |
|------|-----|
| 技能名称 | `/sc:interaction-design` |
| 技能类型 | 专业技能 |
| 适用场景 | IDE 交互设计、信息架构、用户流程、面板系统 |
| 触发关键词 | "交互", "UX", "用户体验", "流程", "布局", "信息架构" |

## 技能定位

### 与 UI 设计的区别

| 维度 | UI 设计 (`/sc:ui-design`) | 交互设计 (`/sc:interaction-design`) |
|------|-------------------------|-----------------------------------|
| 关注点 | 视觉风格、颜色、动画 | 用户流程、信息架构、交互模式 |
| 输出 | 设计稿、CSS、动画效果 | 流程图、线框图、交互规范 |
| 问题类型 | "这个按钮颜色不够好" | "用户如何完成这个任务" |

### 协作关系

```
用户需求 → 交互设计 (/sc:interaction-design) → UI 设计 (/sc:ui-design) → 实现
           ↓                                    ↓
      用户流程设计                          视觉风格设计
      信息架构                              颜色/动画
      交互模式                              组件样式
```

## 核心能力

### 1. 用户流程设计

#### 任务流程分析

**适用场景**: 用户需要完成多步骤任务时的流程设计

```
典型场景:
- 符号执行配置流程
- 知识库编辑流程
- 结果分析流程
- 项目设置流程
```

**设计原则**:
- 3 步以内完成核心操作
- 明确的进度指示
- 可随时保存/取消
- 操作可逆（有撤销）

#### 流程模式

| 模式 | 适用场景 | 示例 |
|------|---------|------|
| 线性流程 | 固定步骤的任务 | 向导式配置 |
| 分支流程 | 需要决策点的任务 | 条件分支分析 |
| 循环流程 | 重复操作的任务 | 迭代测试 |
| 并行流程 | 多任务同时进行 | 多维度分析 |

### 2. 信息架构

#### 导航设计

**全局导航结构**:

```
┌─────────────────────────────────────────┐
│ Logo │ 符号执行 │ 知识库 │ 分析 │ 设置  │  ← 主导航
├─────────────────────────────────────────┤
│ ← 返回                    操作历史 >    │  ← 面包屑
└─────────────────────────────────────────┘
```

**导航原则**:
- 不超过 5 个主导航项
- 当前页面高亮显示
- 面包屑显示层级路径
- 搜索功能全局可用

#### 内容组织

| 层级 | 内容类型 | 示例 |
|------|---------|------|
| L1 | 全局视图 | 仪表盘、项目概览 |
| L2 | 功能模块 | 符号执行、知识库 |
| L3 | 详细面板 | 配置表单、结果列表 |
| L4 | 上下文内容 | 提示信息、详情展开 |

### 3. 交互模式库

#### 基础交互模式

##### 3.1 拖放模式

```
适用场景: 节点布局、流程编排

交互规范:
┌────────────────┐     ┌────────────────┐
│ 可拖动区域      │ →   │ 放置时高亮      │
│ [FlowNode A]   │     │ ┌────────────┐ │
│                │     │ │[FlowNode A]│ │
└────────────────┘     │ └────────────┘ │
                       └────────────────┘
```

**实现要点**:
- 拖动时投影/透明度变化
- 放置目标区域高亮
- 自动吸附对齐
- 支持跨容器拖动

##### 3.2 实时搜索/过滤

```
适用场景: 符号搜索、知识库筛选

交互规范:
┌─────────────────────────────────────┐
│ Q 搜索符号...                    [×] │
├─────────────────────────────────────┤
│ 类型: [全部 ▼]  状态: [全部 ▼]      │
├─────────────────────────────────────┤
│ results@0x1000  [函数]  [已解析]    │
│ input_buffer    [变量]  [已解析]    │
└─────────────────────────────────────┘
```

**实现要点**:
- 实时响应（<100ms）
- 输入即过滤
- 支持快捷键（Cmd/Ctrl+F）
- 高亮匹配文本

##### 3.3 详情展开

```
适用场景: 节点详情、调用栈查看

交互规范:
┌─────────────────────┐
│ main (entry)  [▼]   │  ← 点击展开
├─────────────────────┤
│ 位置: 0x1000        │
│ 指令数: 42          │
│ 分支数: 3           │
└─────────────────────┘
```

**实现要点**:
- 平滑动画展开
- 展开时自动滚动
- 支持多级展开
- 展开状态可保存

##### 3.4 上下文面板

```
适用场景: 属性编辑、右键菜单

交互规范:
                          ┌──────────────┐
                          │ 属性面板      │
                          ├──────────────┤
    [主内容区]            │ 名称: node_a │
                          │ 类型: Branch │
                          │ [应用] [重置]│
                          └──────────────┘
```

**实现要点**:
- 面板可悬浮/停靠
-  ESC 关闭
-  内容实时预览
-  支持快捷键打开

##### 3.5 进度指示

```
适用场景: 长时间操作

交互规范:
┌─────────────────────────────────────────┐
│ 符号执行中...                           │
│ ████████████░░░░░░░░░░░░░░░░  50%      │
│ 已探索 150 条路径 / 共 300 条            │
│ └─ 正在分析: input_buffer@0x2000        │
│                                        │
│                    [取消]  [后台运行]   │
└─────────────────────────────────────────┘
```

**实现要点**:
- 明确的进度百分比
- 当前步骤说明
- 可取消/后台运行
- 完成后通��用户

##### 3.6 错误恢复

```
适用场景: 操作失败、配置错误

交互规范:
┌─────────────────────────────────────────┐
│ ⚠ 配置错误                              │
├─────────────────────────────────────────┤
│ KLEE 路径约束超时                        │
│                                        │
│ 建议:                                   │
│ - 增加 timeout 参数                     │
│ - 简化约束条件                          │
│                                        │
│                    [重试]  [查看详情]   │
└─────────────────────────────────────────┘
```

**实现要点**:
- 错误信息清晰明确
- 提供解决建议
- 操作路径明确
- 错误可追踪

### 6. 反馈系统

#### 反馈类型

| 类型 | 触发条件 | 展示方式 |
|------|---------|---------|
| 成功 | 操作完成 | 短暂 toast + 图标 |
| 错误 | 操作失败 | 面板提示 + 红色 |
| 警告 | 需要注意 | 黄色提示条 |
| 信息 | 状态更新 | 状态栏/面板 |
| 加载 | 正在处理 | 进度指示器 |

#### Toast 规范

```
成功:  ✓ 操作已完成       (2秒后消失)
错误:  ✗ 操作失败         (不自动消失)
警告:  ⚠ 请注意           (4秒后消失)
信息:  ℹ 更新可用         (3秒后消失)
```

### 7. 无障碍设计

#### 键盘无障碍

- 所有交互可通过键盘完成
- 焦点有清晰的视觉指示
- Tab 顺序符合逻辑流程
- 支持跳过导航区块

#### 屏幕阅读器

- 所有交互元素有 ARIA 标签
- 动态内容有 Live Region 通知
- 图片/图标有替代文本
- 颜色不作为唯一信息载体

## FlowSight 交互规范

### 符号执行流程

```
1. 选择目标
   └─ 明确的视觉反馈

2. 配置参数
   └─ 实时验证 + 错误提示

3. 开始执行
   └─ 进度指示 + 可取消

4. 查看结果
   └─ 分页/虚拟滚动 + 快速筛选

5. 深入分析
   └─ 面板展开 + 上下文跳转
```

### 知识库编辑流程

```
1. 浏览/搜索
   └─ 实时搜索 + 分类筛选

2. 选择条目
   └─ 预览面板 + 确认状态

3. 编辑内容
   └─ 表单验证 + 自动保存

4. 预览效果
   └─ 实时预览 + 对比视图

5. 保存/发布
   └─ 确认弹窗 + 成功通知
```

### 错误处理流程

```
错误发生
    ↓
┌──────────────┐
│ 显示错误面板  │
│ 包含:        │
│ - 错误描述    │
│ - 错误位置    │
│ - 解决建议    │
└──────────────┘
    ↓
┌────────────────────────────────────┐
│ 可能的操作:                        │
│ - 查看详情    [重试]    [复制]     │
└────────────────────────────────────┘
    ↓
用户操作或关闭
```

## 常见问题

### Q: 交互设计和 UI 设计如何分工？

A: 交互设计关注"用户做什么"，UI 设计关注"看起来怎么样"。交互设计输出流程图、线框图；UI 设计输出视觉稿、设计规范。

### Q: 交互规范如何落地？

A: 1) 交互设计输出规范文档 2) UI 设计输出视觉稿 3) 开发实现交互逻辑 4) 测试验证交互行为

### Q: 如何保证交互一致性？

A: 1) 建立交互模式库 2) 制定交互规范文档 3) 代码评审检查一致性 4) 组件库统一交互
