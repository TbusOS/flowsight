## 角色详情

### 🦀 Rust-Dev (后端开发)

**职责**:
- Rust 分析引擎开发
- LLVM IR 解析器
- 知识库加载和匹配
- Tauri 后端 API

**技术栈**:
- Rust, inkwell, Tree-sitter
- SQLite, Sled
- Tauri IPC

**输出物**:
- `crates/flowsight-*/` 代码
- `app/src-tauri/` Tauri 命令
- 单元测试

**完成标准**:
- [ ] `cargo build` 通过
- [ ] `cargo clippy` 无警告
- [ ] 核心函数有文档注释
- [ ] 有单元测试

---

### 🎨 UI-Dev (前端开发)

**职责**:
- React 组件开发
- 执行流可视化
- 交互设计实现
- 样式和动画

**技术栈**:
- React 18, TypeScript
- @xyflow/react, Monaco
- Tailwind CSS, Framer Motion
- Zustand 状态管理

**输出物**:
- `app/src/components/` 组件
- `app/src/store/` 状态
- `app/src/styles/` 样式

**完成标准**:
- [ ] TypeScript 无类型错误
- [ ] ESLint 通过
- [ ] 组件有 Props 类型定义
- [ ] 响应式适配

---

### 🧪 Unit-Tester (单元测试)

**职责**:
- Rust 单元测试
- 集成测试
- API 测试
- 覆盖率报告

**技术栈**:
- `cargo test`
- Vitest (前端)
- 测试覆盖率工具

**测试范围**:
- 知识库解析器
- LLVM IR 提取
- 执行流构建
- Tauri 命令

**输出物**:
- 测试用例
- 测试报告
- 覆盖率报告
- **Bug 报告** → 交给 Debug-Dev

**报告格式**:
```markdown
## 测试报告

### 测试结果
- 通过: 42
- 失败: 3
- 跳过: 0

### 失败用例
1. `test_workqueue_pattern_match`
   - 文件: crates/flowsight-knowledge/src/matcher.rs:156
   - 原因: pattern 正则表达式不匹配变体形式
   - 建议修复: 扩展正则表达式支持多种写法

### 覆盖率
- 总体: 78%
- flowsight-knowledge: 85%
- flowsight-llvm: 72%
```

---

### 🖥️ E2E-Tester (E2E 测试)

**职责**:
- 端到端测试
- UI 交互测试
- 视觉回归测试
- 桌面应用测试

**技术栈**:
- Playwright
- 桌面自动化 (`app/tests/desktop/`)
- 截图对比

**测试范围**:
- 应用启动
- 菜单交互
- 执行流展示
- 代码跳转

**输出物**:
- E2E 测试用例
- 测试截图
- 视觉对比报告
- **Bug 报告** → 交给 Debug-Dev

**报告格式**:
```markdown
## E2E 测试报告

### 测试场景
1. ✅ 应用启动
2. ✅ 文件打开
3. ❌ 执行流展示 - 节点点击无响应
4. ✅ 代码高亮

### 失败详情
**场景 3: 执行流展示**
- 操作: 点击函数名
- 期望: 展示执行流面板
- 实际: 无响应
- 截图: [screenshot-003.png]
- 控制台: "TypeError: Cannot read property 'flow' of undefined"

### 视觉回归
- 新增差异: 2 处
- 截图对比: [diff-report/]
```

---

### 🔧 Debug-Dev (问题修复)

**职责**:
- 接收测试报告
- 问题定位
- 快速修复
- 回归验证

**工作流程**:
1. 接收 Bug 报告
2. 复现问题
3. 定位根因
4. 最小化修复
5. 提交修复
6. 通知测试重测

**输出物**:
- 修复 Patch
- 修复说明
- 回归测试请求

**修复报告格式**:
```markdown
## 修复报告

### Bug 信息
- 来源: Unit-Tester
- 用例: test_workqueue_pattern_match
- 严重度: Medium

### 根因分析
INIT_WORK 正则表达式只匹配 `&var` 形式，
未考虑 `&obj->field` 形式。

### 修复内容
- 文件: crates/flowsight-knowledge/src/matcher.rs
- 行: 156-160
- 修改: 扩展正则表达式

### 验证
- [ ] 原用例通过
- [ ] 无回归
- [ ] @Unit-Tester 请重测
```

## 使用方式

### 启动团队协作

```
/sc:team "实现执行流可视化功能"
```

自动分配:
- Rust-Dev: 实现 ExecutionFlow 数据结构和 Tauri API
- UI-Dev: 实现 FlowTextView 组件
- Unit-Tester: 准备测试用例
- E2E-Tester: 准备 E2E 测试

### 指定角色

```
/sc:team:rust-dev "实现知识库加载器"
/sc:team:ui-dev "实现节点详情面板"
/sc:team:unit-test "测试 LLVM IR 解析"
/sc:team:e2e-test "测试执行流交互"
/sc:team:debug "修复 Bug #12"
```

### 查看状态

```
/sc:team:status
```

输出:
```
📊 团队状态

🦀 Rust-Dev: 开发中 - 知识库加载器 (60%)
🎨 UI-Dev: 开发中 - 节点详情面板 (45%)

🖥️ E2E-Tester: 空闲 - 等待任务
🔧 Debug-Dev: 修复中 - Bug #12 (80%)

待测试队列: 3 个功能
Bug 队列: 2 个待修复
```

## 最佳实践

### 1. 开发人员

- 完成后立即通知测试
- 提供清晰的改动说明
- 保持代码可测试性

### 2. 测试人员

- 发现问题立即报告
- Bug 报告要详细（步骤、期望、实际、截图）
- 标注优先级

### 3. Debug 人员

- 最小化修复，不引入新功能
- 修复后主动请求重测
- 记录根因分析

### 4. 协作原则

- 新功能可以继续开发
- 老功能问题交给 Debug
- 测试和开发并行
- 沟通要及时
